# 存储管理：local 和 local-lvm 到底怎么分的

刚装完 PVE 的人几乎都会问同一个问题：硬盘怎么被切成了 `local` 和 `local-lvm` 两块，而且 `local` 小得可怜？

## 官方为什么这么切

- **local（Directory）**：放 ISO 镜像、备份文件、容器模板，就是个普通文件系统（EXT4/XFS）。
- **local-lvm（LVM-Thin）**：放虚拟机磁盘镜像（RAW 格式），支持快照和精简置备，性能好。

分开是为了**安全**：镜像文件再怎么涨，也撑不爆系统盘，PVE 宿主机不会因此崩溃。

## 什么情况该合并

只有一块小容量 SSD（128G、256G 这种）的时候，这套切分就显得很僵硬——ISO 想多放两个都腾不出地方。合并之后，同一个分区里放 ISO、镜像、备份，空间随便分配。

::: danger 合并会清空 local-lvm 上的所有虚拟机
这是不可逆操作。脚本会先要求你清空 `local-lvm`，也就是说**上面所有虚拟机都得先迁走或删掉**。开始之前请确认备份已经做好并且验证可用。
:::

脚本的执行顺序是这样的：

1. 提醒你清空 `local-lvm` 上的所有虚拟机
2. 删除 LVM-Thin 的 `data` 卷，释放空间
3. 把释放出来的空间全部扩给 `/` 分区
4. 改 `/etc/pve/storage.cfg`，让 `local` 能存所有类型的文件

## 硬盘休眠（hdparm）

挂了机械盘的机器，多半希望它闲时能停转，省点电也少点噪音。三个坑：

- **SAS 盘不支持 hdparm**。服务器拆机的 SAS 盘上跑 `hdparm -S` 是无效的，运气不好还会报错。
- **系统盘休眠不了**。PVE 一直在写日志，HDD 只要是系统盘就基本不可能停转。
- **配置要落盘**。脚本把休眠配置写进 `/etc/hdparm.conf`，重启之后依然生效。

## 怎么选

存储配置没有标准答案。多块盘就保持分离，让系统盘和数据盘各管各的；只有一块小盘，合并通常更划算。
