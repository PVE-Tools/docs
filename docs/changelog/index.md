# 更新日志

> 本页用于同步脚本正式发布版本。v11.0.0 为交互层框架化与高风险运维护栏的大版本升级；v7.0.0 曾覆盖 CLI、安全边界、虚拟机运维、宿主机网络与 GPU 直通体系。

## 2026年7月28日 - v11.0.0
### 交互层框架化（Liino）：菜单统一、确认两档、GPU/GRUB 护栏与 CI 真闸门

Build 代号：**Liino**。本版本把「能跑」推进到「可预期、可回滚、可审计」——统一交互骨架，收紧高风险写入，并修正远程安装 / 自更新链路。

#### P0 / 交互层：`lib/menu.sh` 与全模块菜单迁移
- 新增统一菜单框架 `lib/menu.sh`：`run_menu` / `menu_prompt` / `prompt_value` / `prompt_yes_no` / `prompt_pick_from_list` / `show_report`。
- 约 48 处手写 `while true` 菜单循环迁移为 `*_render` + `*_dispatch`，覆盖主菜单 1–10 及 GPU、CVE、防火墙、内核等二级菜单。
- EOF（Ctrl+D / 输入流关闭）与 Ctrl+C 守卫：子菜单视为返回上级，主循环优雅退出，杜绝无效选择死循环刷屏。
- `MENU_SKIP_PAUSE`：进出子菜单与返回不再多按一次「任意键」；动作完成后才 pause。
- 返回项文案按嵌套深度自动生成（「返回主菜单」/「返回上级菜单」）；读取提示统一为 `请选择操作 [0-N]: `。
- 风险横幅（VM / 宿主机网络）每会话仅完整展示一次，避免菜单重绘整屏刷同一段警告。

#### P0 / 确认体系与系统配置写入规范
- 确认两档成文并落地：
  - **轻档** `confirm_action`（输入 `yes`）：可逆配置写入。
  - **重档** `confirm_high_risk_action`（指定确认词）：GRUB / VFIO、驱动黑名单 + initramfs、第三方 deb/内核、LVM、qm 磁盘槽位、Ceph、防火墙清空、SSH 加固等。
- 成块配置一律 `apply_block` / `remove_block`（`# PVE-TOOLS BEGIN/END <MARKER>`），写前自动备份，可幂等清理。
- GRUB 参数改为数组化按 key 精确增删查：新增 `grub_has_param`，避免旧正则误伤相邻参数。
- 默认启动内核优先 `proxmox-boot-tool kernel pin`（GRUB 与 systemd-boot 均适用），失败再回退 `grub-set-default`。

#### P0 / GPU 直通与 IOMMU 安全边界
- 新增 `gpu_detect_active_stacks` / `gpu_warn_active_stacks`：进入任一直通方案前检测已有配置（含旧版无 marker 的 GRUB 特征兜底），降低多方案叠加冲突。
- IOMMU 开/关强制重档确认（`IOMMU-ON` / `IOMMU-OFF`）；模块写入走 marker，清理时先 marker 再兼容历史裸行。
- 去掉一键直通写死的 `vfio-pci ids=8086:3185`；核显 / 声卡黑名单改为可选确认，避免宿主机本地显示默认黑屏。
- Intel 核显清理路径增强：同步移除本工具写入的相关黑名单块，避免「以为恢复了其实仍被屏蔽」。

#### P1 / 远程安装、自更新与分发纠偏
- 远程模式与自更新统一改为 GitHub Releases 完整单文件：`releases/latest/download/PVE-Tools.sh`（main 不再跟踪 `dist/`，raw 入口仅约 300 行 bootstrap）。
- 修正 vGPU Unlock 资源路径：指向真实存在的 `Modules/VGPU/*.so`（原错误 `Modules/NVIDIA/` 不存在）。
- `build.sh` / `dev.sh` / `PVE-Tools.sh` 三入口同步加载 `lib/menu.sh`。
- 优化菜单补齐 UPS 电源诊断入口；CVE 菜单编号连续化；主菜单文案突出 CVE 与 IT87。

#### P1 / CI/CD 护栏「从空转到真闸门」
- PR 验证补全：lib/src 全量 shellcheck error、源码与 dist 函数集合双向 diff、`UPDATE` 首行必须含当前版本、对 dist 的 `eval` / 未引号 `rm -rf $var` / `source` 扫描（命中即失败）。
- 正式 / Beta 发版前再跑语法、shellcheck、函数一致性；正式版强制 tag == `CURRENT_VERSION` == `VERSION`。
- 正式 release 排除 `*-beta*` / `*-alpha*` / `*-rc*`，避免与 beta 流水线抢同一 tag。
- 发布物附带 `SHA256SUMS.txt`；文档移除已过时的 shc 二进制编译叙事。

#### P2 / 文档、仓库卫生与维护声明
- 根 `CLAUDE.md` / `AGENTS.md` / 模块文档按现实重写：入口行数、远程模式、menu 规范、术语表、测试策略。
- 日文 README 文件名由错误的 `REAMDE-JP.md` 更正为 `README-JP.md`。
- 清理历史截图、`proxmoxlib.js`、`release ROM` 等无关大文件；`.gitignore` 允许 `Docs/` 入库。
- 明确 **Shell 版本恢复持续维护**；此前「v8.8.8 后停更转 Go」计划已撤回。

#### 升级提醒
- 大版本升级：交互与确认节奏有变化，高风险操作会要求输入指定确认词，请按屏幕提示操作。
- 远程一键安装与脚本内自更新依赖 GitHub Releases 资产；发版完成后请确认 `releases/latest` 已挂上 `PVE-Tools.sh`。
- 若曾使用旧版一键 IOMMU / 核显方案，升级后进入对应菜单查看「已存在方案」提示，切换方案前建议先清理旧配置并备份 GRUB。
- 建议验证：`bash dev.sh` 走通主菜单进出；维护窗口内抽测 IOMMU / 换源 / 防火墙等重档路径。

## 2026年7月8日 - v10.0.0
### 模块化架构重构 × v9.0.0 特性合并发布；Shell 版本恢复持续维护

Build 代号：**模块化重塑**。本版本彻底重构代码组织架构，合并原计划独立发布的 v9.0.0 全部特性，同时正式撤回「v8.8.8 后停更转 Go」的归档计划。

#### 架构层：模块化重构
- 拆分 `lib/` 基础设施层与 `src/modules/` 功能模块，将单文件脚本按职责解耦为可独立加载的模块单元。
- 实现模块间 `init.sh` 依赖管理，各功能按需加载，降低耦合度与维护成本。

#### 功能层：v9.0.0 特性集合并
- **镜像源系统重构**：改为并行数组架构，新增智能镜像选择与通用下载函数，提升换源可靠性与扩展性。
- **CoolerControl 风扇控制**：新增一键安装/更新/卸载，为桌面级散热管理提供脚本化入口。
- **垃圾清理系统**：新增基础清理、备份修剪、快照修剪、孤立磁盘扫描等功能，帮助回收存储空间。
- **磁盘直通增强**：整盘发现、存储控制器直通、NVMe 直通能力补强，新增系统盘保护避免误操作。
- **存储挂载向导**：支持 ext4 / xfs 分区一键挂载，简化新增磁盘的接入流程。
- **安全中心菜单**：整合安全相关功能入口，统一收口 CVE 修补、内核安全配置等路径。
- **主菜单重组**：新增「安全中心」「第三方工具」入口；虚拟机高级操作拆分为聚焦型子菜单，提升操作效率。
- **移除内嵌文档站**：删除 `Web/` 目录下的 VitePress 文档站，仓库更精简；文档通过独立的 `docs-next` 站点继续维护。

#### 工程层：代码质量与发布流程
- cpupower 安全写入加固、`upgrade-pve` 强制升级确认。
- 修复审查机器人反馈的代码问题：安全规范、回归边界、变量作用域等。
- 发布流程纠偏：移除 shc/ssc 二进制编译链路，改为发布原始 Shell 脚本，消除 glibc 兼容性风险。
- 仓库引用更新：`Mapleawaa` → `PVE-Tools`，域名与安装命令同步修正。

#### 升级提醒
- 从 v8.8.8 升级到 v10.0.0 是一次大版本跳跃（v9.0.0 从未正式发布，其全部特性已合并入本版本）。
- Shell 版本已恢复持续维护，此前「停止更新」公告作废。
- 模块化重构后内部结构变化较大，如有自定义脚本引用内部函数请重新适配。
- 建议验证：进入主菜单逐项检查各功能入口是否正常加载。

- 脚本版本保持为 `7.6.0`，本次仅做同版本补充，不额外迭代。

#### 升级提醒
- 如果你之前已经手动写过旧式 udev 规则，这次更新后建议重新检查一次网卡和 Bridge 的绑定结果。

- 新增的公网镜像选项只会接入已确认可用的组件，避免把未验证的地址写入系统配置。

## 2026年4月30日 - v7.3.0
### 内核安全响应：新增 Copy Fail（CVE-2026-31431）检测、风险评估与缓解入口

- 新增 Copy Fail / `CVE-2026-31431` 漏洞处置菜单，挂载到"启动与内核 -> 内核管理"路径，便于围绕当前运行内核直接排查与处理。
- 新增漏洞状态检测：综合当前运行内核版本、已安装内核包 changelog、`CONFIG_CRYPTO_USER_API_AEAD` / `CONFIG_CRYPTO_AUTHENCESN`、`algif_aead` / `authencesn` 模块状态，判断系统更接近"已修复 / 已缓解 / 仍有风险 / 通常不受影响"哪一类。
- 新增受攻击危险评估：结合交互用户数量、LXC 容器数量与运行状态、SSH 服务暴露情况，对本地提权 / 容器逃逸前置条件做更直观提示。
- 新增手动处理说明：在界面中明确区分"正式修复优先"和"临时缓解优先"，提醒用户优先升级到供应商明确声明已修复该 CVE 的内核。
- 新增两种自动临时缓解方式：
  - 禁用 `algif_aead`（参考 copy.fail 官方建议）
  - 禁用 `authencesn`（参考发行版 workaround 思路）
- 新增临时缓解回滚入口，便于在完成正式内核修复后撤销持久化模块阻断策略。
- 保留并复用现有内核同步更新流程，但在交互文案中明确说明"升级到仓库最新内核"不自动等于"已经修复该 CVE"，避免误判风险边界。

#### 升级提醒
- 该版本重点是安全检测与缓解辅助，不包含 exploit、PoC 或自动化高风险利用逻辑。
- 若当前内核供应商尚未发布明确修复包，建议先启用临时缓解，再安排维护窗口升级并重启到修复后的内核。
